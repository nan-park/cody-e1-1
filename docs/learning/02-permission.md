# 2단계 · 파일 권한

> 실습 로그: [`docs/logs/02-permission.log`](../logs/02-permission.log)

## 배운 개념

### 왜 권한이 존재하나

리눅스는 원래 **여러 사람이 한 컴퓨터에 동시에 접속해 쓰는** 환경을 전제로 만들어졌다.
"이 파일은 내가 만든 거니 남은 못 보게" 같은 규칙이 필요했고, 그게 권한이다.
컨테이너 안에서도 그대로 적용된다 — "스크립트가 실행이 안 돼요", "웹서버가 파일을 못 읽어요"의 상당수가 권한 문제다.

### 10칸 문자열 읽는 법

```
-      rwx        r-x        r-x
│      └┬┘        └┬┘        └┬┘
종류   소유자      그룹      그 외(other)
```

- 맨 앞 1칸: `-` 일반 파일 / `d` 디렉토리
- 나머지 9칸: **3칸씩 3묶음**, 각 묶음은 항상 `r w x` 순서, 없으면 `-`

| 기호 | 파일에서 | **디렉토리에서** |
|---|---|---|
| `r` | 내용 읽기 | 안에 뭐가 있는지 **목록 보기** |
| `w` | 내용 수정 | 안에 파일 **생성/삭제** |
| `x` | 프로그램으로 **실행** | 그 폴더 안으로 **진입(cd)** |

### 숫자 표기의 원리

```
r = 4      w = 2      x = 1     (더하기만 하면 됨)
```

| 조합 | 계산 | 숫자 |
|---|---|---|
| `rwx` | 4+2+1 | 7 |
| `rw-` | 4+2 | 6 |
| `r-x` | 4+1 | 5 |
| `r--` | 4 | 4 |
| `---` | 0 | 0 |

```
755 = rwx r-x r-x   → 실행파일·디렉토리의 기본
644 = rw- r-- r--   → 일반 문서의 기본
600 = rw- --- ---   → 비밀키, 민감한 설정
```

### 실험으로 확인한 것 4가지

| 실험 | 조작 | 결과 | 배운 것 |
|---|---|---|---|
| 1 | `run.sh` 644 → 755 | `permission denied` → 정상 실행 | 내용이 완벽해도 `x` 없으면 실행 불가 |
| 2 | `hello.txt` 644 → 000 | `cat` 거부됨 | **소유자라도** `r` 없으면 못 읽음 |
| 3 | `backup/` 755 → 555 | `touch` 거부됨 | 디렉토리 `w` = 파일 생성/삭제 권한 |
| 4 | `backup/` 755 → 644 | `cd` 거부, 이름만 보임 | 디렉토리 `x` = 진입 권한 |

**실험 4가 가장 중요하다.** `x`를 뺐더니:

```
$ ls backup
ls: fts_read: Permission denied
hello_backup.txt          ← 이름은 보인다 (r 이 살아있음)
newfile.txt

$ cat backup/hello_backup.txt
cat: backup/hello_backup.txt: Permission denied    ← 내용은 못 읽는다 (x 가 없음)
```

> 디렉토리에서 `r`은 **명단을 볼 권리**, `x`는 **안으로 들어갈 권리**.
> 명단은 봤지만 문이 잠겨 각 방에 못 들어가는 상태.
> 그래서 디렉토리는 사실상 항상 `755`를 쓴다. `x` 없는 디렉토리는 거의 쓸모가 없다.

## 헷갈리기 쉬운 지점

### 1. 파일 삭제 권한은 "파일"이 아니라 "폴더"가 결정한다

서랍장(폴더)과 서류(파일)로 생각하면, 서류를 넣고 빼는 건 **서랍장을 열 권한**의 문제다.
그래서 읽기 전용(`444`) 파일도 폴더에 `w`가 있으면 삭제된다.

### 2. 소유자라고 자동으로 읽히지 않는다

실험 2에서 `chmod 000` 후 내가 만든 파일도 `Permission denied`가 났다.
단, 소유자는 `chmod`로 **다시 열 권리**가 있다(남의 파일은 이 복구조차 못 함).

### 3. 디렉토리의 `x`는 "실행"이 아니라 "통과"

가장 많이 헷갈리는 부분. 폴더를 실행한다는 개념이 없으니 **진입/통과**로 번역해서 이해할 것.

### 4. `./run.sh`에서 `./`를 왜 붙이나

그냥 `run.sh`라고 치면 셸은 "시스템에 설치된 명령어인가?" 하고 정해진 폴더만 뒤지다 못 찾는다.
`./`를 붙여 **"지금 이 폴더의 그 파일"** 이라고 상대경로로 명시해야 한다. (1단계의 `.`이 여기서 쓰임)

### 5. `ls -l backup` vs `ls -ld backup`

- `ls -l backup` → backup **안의 내용물**
- `ls -ld backup` → backup **폴더 자신**의 권한 ← 권한 확인할 땐 이것

## 내가 던진 질문들

### Q. `run.sh`가 뭐야?

권한 실험용으로 만든 **셸 스크립트 파일**. 명령어들을 파일에 미리 적어두고 실행하는 것이며, 관례상 `.sh` 확장자를 붙인다.

```sh
#!/bin/sh                       ← 셔뱅(shebang): 이 파일을 /bin/sh 로 실행하라는 지시
echo permission-practice-ok     ← 실제로 할 일
```

**왜 이 파일로 실험했나**: `x` 비트의 효과를 보려면 "실행될 수 있는 파일"이 필요했다.
`hello.txt` 같은 텍스트 파일은 `x`를 줘도 관찰할 변화가 없다.
`run.sh`는 내용이 100% 정상인데도 **오직 권한 한 글자 때문에** 결과가 갈리는 걸 보여준다.

실무에선 `build.sh`, `deploy.sh` 같은 파일에 명령어 뭉치를 담아 팀 전체가 같은 방식으로 실행하게 한다.

### Q. `printf`, `cat`, `ls -l`, `chmod`, `touch`, `umask` 뜻?

명령어 이름은 대부분 **영어 줄임말**이라 어원을 알면 외워진다.

| 명령 | 어원 | 하는 일 |
|---|---|---|
| `pwd` | **p**rint **w**orking **d**irectory | 현재 위치 출력 |
| `ls` | **l**i**s**t | 목록 보기 |
| `cd` | **c**hange **d**irectory | 폴더 이동 |
| `mkdir` | **m**a**k**e **dir**ectory | 폴더 생성 |
| `touch` | 톡 건드리다 | 빈 파일 생성 / 수정시각 갱신 |
| `cat` | con**cat**enate (이어붙이다) | 파일 내용 출력 |
| `echo` | 메아리 | 글자 출력 (`>`와 함께 파일 쓰기) |
| `printf` | **print f**ormatted | 서식 지정 출력 (`\n` = 줄바꿈) |
| `cp` | **c**o**p**y | 복사 |
| `mv` | **m**o**v**e | 이동 / 이름 변경 |
| `rm` | **r**e**m**ove | 삭제 |
| `find` | 찾다 | 하위 폴더까지 검색 |
| `chmod` | **ch**ange **mod**e | 권한 변경 |
| `umask` | **u**ser **mask** | 새 파일의 기본 권한 설정값 |

- `cat`은 고양이가 아니라 "이어붙이다". 원래는 여러 파일을 이어 출력하는 명령.
- `touch`는 이미 있는 파일에 써도 **내용이 지워지지 않는다**. 반면 `echo "" > file`은 내용을 날린다.
- `chmod`는 숫자 방식(`chmod 755`) 외에 기호 방식(`chmod +x`)도 있고, 실무에선 `+x`가 더 자주 쓰인다.

### Q. `umask`를 하는 게 무슨 의미가 있어?

**두 가지로 나눠 볼 것.**

**① 실습에서 친 이유** — 권한을 지정한 적이 없는데 매번 파일은 `644`, 폴더는 `755`가 나왔다. 그 원인을 확인하는 절차였다. 즉 "644는 마법의 숫자가 아니라 `666 - 022`의 계산 결과"임을 증명한 것.

```
파일 기본값     666 (rw-rw-rw-)        디렉토리 기본값  777
umask          -022                                   -022
──────────────────────────                    ──────────────
결과            644 (rw-r--r--)                        755
```

**② 이 장치가 존재하는 이유** — **안전한 기본값**을 강제하기 위해서.
- 파일 기본값이 `777`이 아니라 `666`인 것부터가 "새 파일에 실행 권한을 함부로 주지 않는다"는 보안 원칙. 그래서 스크립트를 만들면 항상 `chmod +x`를 한 번 해줘야 한다.
- `022`가 빼는 건 그룹·기타의 `w`. 내 파일을 남이 고치지 못하게 한다.

| umask | 결과(파일/폴더) | 쓰는 상황 |
|---|---|---|
| `022` | 644 / 755 | 기본값 |
| `002` | 664 / 775 | 팀 공용 서버(그룹원끼리 수정 가능해야 할 때) |
| `077` | 600 / 700 | 보안 민감 서버(나 외엔 접근 불가) |

**솔직한 결론**: 일상 개발에서 `umask`를 직접 만질 일은 거의 없다.
알아야 하는 이유는 **권한 문제가 터졌을 때 배후를 설명하기 위해서**다.

### Q. `754`면 무슨 의미야?

```
7        5        4
rwx      r-x      r--
소유자   그룹     그 외
```

= `-rwxr-xr--`. `755`와 비교하면 **그 외 사람의 `x`만 빠진** 것.

실제로 확인한 출력:

```
$ chmod 754 run.sh && stat -f "%N  숫자=%Lp  문자=%Sp" run.sh
run.sh  숫자=754  문자=-rwxr-xr--
```

**"그룹"이란?** 리눅스는 사용자를 그룹으로 묶을 수 있다. 서버에 `dev` 그룹을 만들어 개발자 5명을 넣으면 그 5명이 "그룹" 칸의 권한을 함께 적용받는다.

**754를 쓰는 상황**: "우리 팀은 실행해도 되지만, 외부 계정은 내용만 참고하고 실행은 말라."
다만 **실무에서 자주 보는 값은 아니다.** 보통은 아예 차단하는 `750`을 쓴다.

자주 쓰는 값:

| 값 | 문자 | 용도 |
|---|---|---|
| `755` | `rwxr-xr-x` | 실행 파일, 디렉토리, 웹 공개 폴더 |
| `644` | `rw-r--r--` | 일반 문서, 설정, HTML/CSS |
| `750` | `rwxr-x---` | 팀 내부용 실행 스크립트 |
| `600` | `rw-------` | SSH 개인키, 비밀번호가 든 설정 |
| `400` | `r--------` | 절대 수정하면 안 되는 인증서 키 |

> `600`은 나중에 GitHub SSH 키에서 **강제로 요구된다**.
> 개인키 권한이 `644`처럼 열려 있으면 SSH가 아예 접속을 거부한다.

**변환 암기법**: `4=r, 2=w, 1=x`만 외우고 나머지는 덧셈.
`7→rwx, 6→rw-, 5→r-x, 4→r--, 3→-wx, 2→-w-, 1→--x, 0→---`

## 스스로 설명할 수 있어야 하는 것 (과제 목표)

> `r/w/x`는 읽기·쓰기·실행이고 각각 `4/2/1` 값을 가진다.
> 소유자·그룹·기타 3묶음으로 더해 표기한 것이 숫자 표기다.
> `755 = rwxr-xr-x`, `644 = rw-r--r--`.
> 단 디렉토리에서는 의미가 달라져 `r`=목록 조회, `w`=파일 생성/삭제, `x`=진입(cd)이다.
