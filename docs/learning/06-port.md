## 배운 개념

### 왜 접속이 안 됐나 — 네트워크 격리

5단계 마지막에 컨테이너 **안**에서는 되는데 **밖**에서는 안 되는 상태를 만들어 두었다.

```
$ docker exec web-nomap wget -qO- http://127.0.0.1:8080/   → 정상 출력 ✅
$ curl --max-time 3 http://localhost:8080/                  → 종료코드 7 ❌
```

원인은 컨테이너가 **자기만의 네트워크 공간**을 갖기 때문.

```
$ docker inspect web-nomap --format "{{...IPAddress}}"   → 192.168.215.2   (컨테이너)
$ ipconfig getifaddr en0                                  → 10.13.2.6      (내 맥)
```

4단계에서 PID가 안에서는 1번, 밖에서는 2399번이었던 것과 같은 원리. 이번엔 **네트워크 네임스페이스**다.

> 아파트 비유: 컨테이너는 **건물 안 사설 통로**, 나는 **바깥 도로**.
> 건물 안에서는 8080호를 잘 찾아가지만, 도로에서는 그 주소로 갈 방법이 없다.

### `-p`로 통로 뚫기

```sh
docker run -d -p 8080:8080 --name web-8080 cody-web:1.0
              └──┬──┘ └─┬─┘
            호스트 포트  컨테이너 포트
```

**항상 `호스트:컨테이너` 순서.** (`COPY 호스트 컨테이너`, `-v 호스트:컨테이너`와 같은 규칙)

`docker ps`의 PORTS 칸 변화:

```
매핑 전:  80/tcp, 8080/tcp
               ↑ EXPOSE로 적어둔 문패일 뿐 (문은 닫혀 있음)

매핑 후:  80/tcp, 0.0.0.0:8080->8080/tcp
                  └────────┬─────────┘
                  호스트 8080 → 컨테이너 8080 (문이 열림)
```

`docker port web-8080` 으로 매핑만 따로 확인할 수도 있다.

**`0.0.0.0`은 "모든 네트워크 인터페이스에서 받겠다"** 는 뜻. 같은 와이파이의 다른 사람도 `10.13.2.6:8080`으로 접속할 수 있다.

> **보안 팁**: 나만 쓸 거면 `-p 127.0.0.1:8080:8080`으로 내 컴퓨터에서만 접속 가능하게 제한.
> 개발 중인 DB 컨테이너 등에 권장.

### ⭐ 핵심: 같은 이미지, 같은 내부 포트, 두 개 동시 실행

```
$ docker ps --format "table {{.Names}}\t{{.Ports}}"
NAMES      PORTS
web-8081   0.0.0.0:8081->8080/tcp     ← 호스트 8081 → 컨테이너 8080
web-8080   0.0.0.0:8080->8080/tcp     ← 호스트 8080 → 컨테이너 8080

$ curl -s http://localhost:8080/healthz && curl -s http://localhost:8081/healthz
ok
ok
```

**두 컨테이너 모두 내부에서는 8080을 쓴다.** 이미지가 같으니 당연하다.
그런데 한 컴퓨터에서 **같은 포트를 두 프로그램이 동시에 쓸 수는 없다.**

```
        내 맥 (호스트)                     컨테이너들
   ┌──────────────────┐          ┌─────────────────────┐
   │  포트 8080  ─────┼──────────┼→ web-8080 의 8080   │
   │  포트 8081  ─────┼──────────┼→ web-8081 의 8080   │  ← 내부는 둘 다 8080
   └──────────────────┘          └─────────────────────┘
      바깥 주소는 달라야 함           안쪽은 같아도 무관
```

> **이것이 "포트 매핑이 왜 필요한가"의 답.**
> 컨테이너 안은 각자 독립된 세계라 서로 충돌하지 않는다.
> 그래서 애플리케이션은 포트를 고정값으로 쓰고, 배치할 때만 바깥 포트를 조정하면 된다.
> 컨테이너로 서비스를 여러 개 굴리는 기반이 이것이다.

### 포트 충돌

```
$ docker run -d -p 8080:8080 --name web-dup cody-web:1.0
docker: Error response from daemon: ... Bind for :::8080 failed: port is already allocated
```

해결 방법 셋:
1. 다른 호스트 포트를 쓴다 (`-p 8081:8080`)
2. 기존 컨테이너를 멈춘다 (`docker stop`)
3. 그 포트를 쓰는 다른 프로그램을 찾아 끈다 (`lsof -i :8080`)

**함정**: 실행은 실패했는데 컨테이너는 남는다.

```
$ docker ps -a
NAMES      STATUS
web-dup    Created      ← create는 성공, start에서 실패한 상태
```

이 상태로 같은 이름을 다시 쓰면 이번엔 "이름이 이미 존재한다"는 다른 에러가 난다. `docker rm`으로 치워야 한다.

### 보너스: 재빌드 없이 내부 포트까지 변경

5단계에서 만든 환경변수 템플릿이 여기서 값을 한다.

```sh
docker run -d -p 8082:9090 -e NGINX_PORT=9090 -e APP_ENV=production --name web-9090 cody-web:1.0
```

```
$ curl -s http://localhost:8082/env
APP_ENV=production                     ← 기본값 dev 를 덮어씀
NGINX_PORT=9090

$ docker exec web-9090 grep listen /etc/nginx/conf.d/default.conf
    listen       9090;                 ← 설정 파일이 실제로 다시 쓰였다
```

**이미지는 똑같은 `cody-web:1.0`인데 설정이 달라졌다.** `-e` 하나로.

```
이미지 1개  →  개발용 컨테이너 (APP_ENV=dev, 8080)
            →  운영용 컨테이너 (APP_ENV=production, 9090)
```

> 테스트한 이미지와 배포하는 이미지가 **완전히 동일**하다는 게 핵심.
> 환경마다 다른 이미지를 만들면 "테스트에선 됐는데 운영에서 안 되는" 문제가 생긴다.

## 헷갈리기 쉬운 지점

### 1. `EXPOSE`와 `-p`는 다른 것

| | 하는 일 |
|---|---|
| `EXPOSE 8080` (Dockerfile) | "이 이미지는 8080을 씁니다"라는 **문서** |
| `-p 8080:8080` (run) | 실제로 통로를 뚫는 **동작** |

> **기억법**: `EXPOSE`는 **문패**, `-p`는 **문**.

### 2. 순서를 뒤집으면 엉뚱하게 동작한다

`-p 8080:8081`은 "호스트 8080 → 컨테이너 8081"이다. 컨테이너가 8081에서 듣고 있지 않으면 접속이 안 된다.
**왼쪽은 내가 브라우저에 칠 번호, 오른쪽은 컨테이너 안 프로그램이 듣고 있는 번호.**

### 3. 컨테이너 내부 포트는 아무 값이나 써도 된다

내부는 격리돼 있으므로 80이든 8080이든 무관하다.
다만 **1024 미만 포트는 원래 관리자 권한이 필요**해서, 컨테이너 안에서 일반 사용자로 실행하려면 8080 같은 큰 번호를 쓰는 편이 안전하다.

### 4. `localhost`가 안에서와 밖에서 다른 곳을 가리킨다

컨테이너 안에서의 `localhost`(127.0.0.1)는 **그 컨테이너 자신**이다. 호스트가 아니다.
그래서 컨테이너에서 내 맥의 서비스를 부르려면 `host.docker.internal` 같은 별도 주소를 쓴다.

## 스스로 점검하는 질문

1. `-p 8081:8080`에서 각 숫자는 무엇을 가리키나?
2. 같은 이미지로 만든 컨테이너 두 개가 내부 포트를 똑같이 써도 되는 이유는?
3. `port is already allocated` 에러가 났을 때 확인할 것 세 가지는?
4. `EXPOSE`만 쓰고 `-p`를 안 쓰면 어떻게 되나?
5. 이미지를 다시 빌드하지 않고 컨테이너의 동작 설정을 바꾸려면?
